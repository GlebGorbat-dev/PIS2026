# Этап 13 — сохранение истории анализа

**Статус:** выполнен.

## Что требовалось по плану

> Для анализа сохраняются минимум фотография или ссылка на неё, дата,
> определённый класс, уверенность, информация о том, был ли результат признан надёжным.

## Что сделано

Успешное распознавание дописывается в `data/history/journal.jsonl`. Рядом
копируется файл снимка: следующая загрузка удаляет текущий кадр из
`data/uploads/`, но запись истории остаётся.

| Поле | Как сохраняется |
| --- | --- |
| Фотография | копия в `data/history/images/`, ссылка `/history/<id>/photo` |
| Дата | момент распознавания с часовым поясом |
| Класс | код класса и русское название |
| Уверенность | вероятность лучшего класса |
| Надёжность | `true`, только если уверенность не ниже 60% |

Порог тот же, что на этапе 12: от 60% ответ надёжный, от 40% до 60% и ниже 40%
сохраняются, но с `reliable: false`. Кадр, который программа отклонила
до модели, в журнал не пишется.

На главной странице последние 30 анализов: миниатюра, дата, культура,
класс, уверенность и метка «Надёжно» или «Ненадёжно». Журнал целиком при этом не обрезается.

## Проверка результата

```bash
pytest -q tests/test_history.py tests/test_app_predict.py::test_analyses_remain_after_the_upload_is_removed
```

Ожидается: две записи переживают удаление текущего снимка; у уверенности 88%
поле `reliable` истинно, у 41% и 28% — ложно.
