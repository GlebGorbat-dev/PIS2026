## Пользовательский сценарий

**Пользователь:** агроном или фермер, который осматривает посевы пшеницы
и хочет быстро понять, что с растением.

**Цель:** по фотографии листа узнать, здоровое растение или чем оно больно,
и понять, насколько можно доверять ответу.

**Основной сценарий**

1. Пользователь открывает приложение и видит, что оно умеет: пять
   распознаваемых состояний, допустимые форматы и размер файла.
2. Выбирает фотографию и нажимает «Определить заболевание».
3. Программа проверяет файл, сохраняет снимок и передаёт его модели.
4. Пользователь видит результат: название состояния, уверенность модели,
   вероятности всех пяти классов, признаки болезни и что делать дальше.
   Рядом — сам снимок, чтобы сверить его с описанием признаков.
5. Пользователь проверяет следующую фотографию («Заменить и определить»)
   или убирает снимок.

**Альтернативные ветки**

| Ситуация | Что делает программа |
| --- | --- |
| Модель не уверена (< 60%) | предупреждает, называет второй вариант и показывает признаки обоих, чтобы пользователь сравнил их с фото |
| Растение здоровое | сообщает, что признаков болезни не найдено, и не советует обработку |
| Файл не изображение, пустой, слишком большой или мелкий, неподдерживаемый формат | объясняет причину и перечисляет допустимые форматы; модель не вызывается |
| Неудачная замена снимка | прежний снимок и его результат остаются на месте |
| Нет файла весов модели | сообщает, что модель недоступна; снимок сохраняется, приложение не падает |
| Пользователь обновил страницу | результат остаётся, модель повторно не вызывается |
| Пользователь хочет сначала просто посмотреть снимок | кнопка «Только загрузить», распознавание — потом кнопкой «Определить» |

## Что изменилось по сравнению с этапом 6

| Было на этапе 6 | Стало в MVP | Зачем |
| --- | --- | --- |
| Два шага: «Загрузить», затем «Определить» | один шаг: выбрал фото → «Определить заболевание». Двухшаговый путь оставлен кнопкой «Только загрузить» | основной сценарий короче на одно действие |
| Результат пропадал при обновлении страницы | результат сохраняется вместе со снимком; после распознавания — перенаправление (303) на главную | обновление страницы не теряет ответ и не повторяет отправку формы |
| Только название класса и вероятности | плюс признаки болезни и совет, что делать | пользователь может сам сверить ответ с фото |
| При низкой уверенности — только второй вариант | плюс признаки обоих вариантов рядом | пользователь выбирает между двумя вариантами по описанию, а не наугад |
| Кнопки можно было нажать дважды | во время запроса кнопки блокируются, на нажатой — «Определяю…» | нет повторных отправок большого файла |

Описания признаков хранятся рядом с названиями классов в
`configs/dataset.yaml` (поле `symptoms`). Советы намеренно общие:
программа направляет к агроному, а не назначает обработку.

## Как запустить с нуля

```bash
git clone https://github.com/GlebGorbat-dev/PIS2026.git
cd PIS2026
python3.12 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
uvicorn src.app.main:app
```

Открыть <http://127.0.0.1:8000>. Датасет для работы приложения не нужен:
веса модели (`models/stage4.pt`, 5,9 МБ) лежат в репозитории. Датасет нужен
только чтобы переобучить модель или пересчитать метрики (этапы 3–5, 7).

## Как сценарий выглядит на примерах

Начало: программа сразу говорит, что умеет и какие файлы принимает.

Уверенный ответ: бурая ржавчина, 91%. Под вероятностями — как выглядит
болезнь и что делать.

Неуверенный ответ: жёлтая ржавчина 38% против бурой 35%. Программа
предупреждает и показывает признаки обеих. На фото на самом деле бурая
ржавчина: с описанием признаков пользователь может это заметить.

Здоровое растение: совета об обработке нет.

Примеры — снимки из тестовой выборки: `BrownRust476.png`,
`BrownRust1696.png`, `Healthy1878.png`.

## Проверка результата

**Тесты.** `pytest -q` — 53 теста проходят. Из них 13 новых
в `tests/test_scenario.py` проверяют сценарий целиком:
- распознавание в один шаг;
- результат после обновления страницы, без повторного вызова модели;
- сброс результата при новом снимке и при «Убрать изображение»;
- признаки болезни при уверенном и неуверенном ответе;
- отсутствие совета об обработке для здорового растения;
- отказ на неподходящем файле до вызова модели;
- работу без весов модели;
- повреждённый файл с результатом;
- полный сценарий с настоящей моделью на двух снимках из датасета.

**Чистая копия.** Проект собран в отдельной папке ровно из тех файлов,
которые попадают в git (94 файла, 13 МБ, без датасета и `.venv`). Из неё:
- тесты: 51 проходит, 2 пропущены — им нужны снимки датасета;
- приложение запускается, `/health` сообщает `model_loaded: true`;
- распознавание в один шаг на снимке `Mildew2334.png` даёт «Мучнистая роса».

**Живой сервер.** Сценарий пройден на запущенном `uvicorn`: загрузка
с распознаванием, обновление страницы, замена снимка.

**Проверка классов.** `python -m src.control.run` на новом сценарии
по-прежнему даёт PASS для всех пяти классов, 149 ответов из 149.

## Ограничения MVP

- Качество модели — исходное, с этапа 5: accuracy 0,711, ошибка примерно
  в трёх случаях из десяти. Улучшение — этапы 9 и 10. Эта цифра указана
  в интерфейсе и будет обновлена вместе с моделью.
- Один пользователь — один текущий снимок (через cookie). Истории проверок
  и учётных записей нет.
- Загруженные снимки хранятся в `data/uploads/` и не удаляются по времени.
  Для запуска на общем сервере понадобится очистка старых файлов.
- Приложение рассчитано на локальный запуск. Развёртывание на сервере
  в план этапа не входило.
