# Детектирование заболеваний зерновых растений

Веб-приложение смотрит на фотографию листа и относит её к одному из состояний выбранной культуры: здоровый лист или конкретная болезнь. Культуры — пшеница, ячмень и кукуруза. У каждой свой набор классов и свой файл весов. Ответ — подсказка модели, а не агрономический диагноз.

Для запуска датасет скачивать не нужно: веса уже лежат в `models/`.

## Запуск

Нужен Python 3.12.

```bash
python3.12 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
uvicorn src.app.main:app --reload
```

Откройте http://127.0.0.1:8000. Выберите культуру, загрузите фотографию и нажмите «Определить заболевание». Один и тот же снимок из командной строки:

```bash
python -m src.model.predict путь/к/снимку.jpg
python -m src.model.predict путь/к/снимку.jpg --crop barley
python -m src.model.predict путь/к/снимку.jpg --crop maize
```

Проверка кода: `pytest -q`.

## Что делает пользователь

1. Выбирает культуру. Форма уходит на `POST /crop`, выбор записывается в cookie `current_crop` на сутки, предыдущий ответ модели сбрасывается. Набор болезней на странице сразу меняется.
2. Загружает файл. Кнопка «Определить заболевание» шлёт `POST /upload` с полем `then=predict`: снимок сохраняется и сразу уходит в модель. «Только загрузить» сохраняет файл без распознавания, потом его можно отправить кнопкой «Определить заболевание» (`POST /predict`).
3. Видит ответ: название состояния, уверенность, вероятности всех классов этой культуры и текстовые признаки, с которыми снимок можно сверить.
4. Может убрать снимок (`POST /reset`) или заменить его новым файлом.

Текущий файл помнится cookie `current_upload`. Сам файл и JSON с результатом лежат в `data/uploads/` (эта папка в git не попадает). Картинка отдаётся по `GET /image`. Состояние сервиса — `GET /health`.

## Путь снимка до ответа

Страница собрана в `src/app/templates/index.html`, сервер — FastAPI в `src/app/main.py`. При старте приложение создаёт `data/uploads/` и проверяет, что файлы весов на месте.

```
браузер
  → проверка файла (src/app/storage.py, src/app/quality.py)
  → сохранение в data/uploads/
  → проверка культуры (src/model/crop_gate.py): чужой объект не получает диагноз
  → MobileNetV3-Small выбранной культуры (src/model/predict.py)
  → softmax по классам этой культуры
  → пороги уверенности (src/app/confidence.py)
  → страница с вердиктом, вероятностями и признаками
```

Плохой кадр до модели не доходит. `storage.validate` отклоняет файл, если он пустой, больше 20 МБ, не читается как изображение, имеет неподдерживаемый формат, содержит больше 50 мегапикселей или его меньшая сторона короче 64 px. Допустимые форматы: JPEG, PNG, BMP, TIFF, WEBP.

Дальше на превью 224×224 считаются яркость и резкость — тот же размер, который потом видит сеть:

| Проверка | Порог | Что видит пользователь |
| --- | --- | --- |
| Средняя яркость | ниже 40 | снимок слишком тёмный |
| Средняя яркость | выше 220 | снимок слишком светлый |
| Дисперсия лапласиана | ниже 40 | снимок слишком размытый |

Пороги заданы в `src/app/settings.py`. Сначала проверяется свет, потом резкость: чёрный кадр не называют размытым.

Следующий шаг — культура. `src/model/crop_gate.py` смотрит, не является ли кадр уверенно узнаваемым чужим объектом. Такой снимок не доходит до модели болезни, и программа не называет, что на нём изображено: «На снимке не пшеница. Это не лист пшеницы, поэтому болезнь не определяется. Загрузите фотографию выбранной культуры.» Обычный лист зерновых ImageNet узнаёт плохо, поэтому такой кадр проходит к диагнозу. Веса проверки — `models/crop_gate.pt`.

## Как модель считает класс

Сеть — `MobileNetV3-Small` из torchvision. Последний линейный слой заменён на число классов культуры (`src/model/architecture.py`). Устройство выбирается само: Apple MPS, затем CUDA, иначе CPU.

Перед сетью снимок переводится в RGB, уменьшается, обрезается по центру до 224×224 и нормализуется средними и стандартными отклонениями ImageNet. На обучении вместо этого случайный кроп, отражение и сдвиг цвета. Веса загружаются один раз и кэшируются.

`softmax` даёт вероятность каждого класса. Класс с максимальной вероятностью — лучший ответ, но страница показывает его по-разному:

| Уверенность лучшего класса | Режим | Что на экране |
| --- | --- | --- |
| 60% и выше | уверенный ответ | название состояния и его признаки |
| от 40% до 60% | низкая уверенность | тот же ответ плюс предупреждение и второй вариант |
| ниже 40% | не распознано | заголовок «Случай не распознан», без выбора обработки; два ближайших класса показаны только для сравнения |

Здоровым лист называется только в уверенном режиме и только если победил класс `healthy`. Иначе страница просит показать растение агроному.

Веб-приложение берёт такие файлы:

| Культура | Веса | Классы |
| --- | --- | --- |
| Пшеница | `models/stage4.pt` | здоровое растение, жёлтая ржавчина, бурая ржавчина, септориоз, мучнистая роса |
| Ячмень | `models/barley.pt` | здоровый лист, бурая ржавчина ячменя, рамулярия |
| Кукуруза | `models/maize.pt` | здоровый лист, ожог листа, серая пятнистость, повреждение совкой |

Русские названия и описание признаков лежат в `configs/dataset.yaml`, `configs/dataset_barley.yaml` и `configs/dataset_maize.yaml`. Модель не знает классов другой культуры: ячмень не может ответить «септориоз», кукуруза не может ответить «ржавчина».

`models/stage10.pt` — более поздняя пшеничная модель. На том же тесте из 149 снимков у `stage4.pt` accuracy 0,711, у `stage10.pt` — 0,819. Сайт по-прежнему отвечает весами `stage4.pt`. Ячмень и кукуруза в этот эксперимент не входят.

На валидации ячменя accuracy `barley.pt` — 0,686 (366 снимков), кукурузы `maize.pt` — 0,958 (288 снимков). Это другие выборки, их нельзя сравнивать с тестом пшеницы.

## Как получились веса

Обучение — `python -m src.model.train`. Конфиг по умолчанию `configs/train.yaml`: ImageNet-веса, замороженный backbone, 10 эпох, Adam, веса классов по частоте, ранняя остановка по validation accuracy. Чекпоинт хранит состояние сети, имена классов и конфиг предобработки, поэтому предсказание не зависит от того, какой yaml лежит рядом.

Ячмень (`configs/train_barley.yaml`) дообучает голову, стартуя с backbone `stage4.pt`. Кукуруза (`configs/train_maize.yaml`) размораживает backbone и тоже стартует со `stage4.pt`. Улучшенная пшеница обучается отдельно:

```bash
python -m src.model.train --config configs/train_stage10.yaml --reports-dir reports/stage10
```

Там backbone разморожен, у него меньший learning rate, больше эпох, сильнее цветовой jitter и сглаживание меток. Сравнение с первой моделью: `python -m src.model.compare`.

Оценка фиксированного теста пшеницы:

```bash
python -m src.model.evaluate
python -m src.model.errors
```

## Откуда берутся фотографии для обучения

Сами снимки в репозитории не хранятся. Приложению они не нужны. Чтобы повторить обучение пшеницы:

```bash
python -m src.data.download    # архив Zenodo, проверка md5, распаковка
python -m src.data.inventory   # классы и целые файлы
python -m src.data.dedup       # точные и близкие дубликаты
python -m src.data.split       # train / val / test, 70 / 15 / 15, seed 42
python -m src.data.preview     # сетки миниатюр
```

Близкие кадры одной сцены не попадают сразу в обучение и в тест. Ячмень и кукуруза качаются своими конфигами (`src/data/fetch_crops.py`): у ячменя патчи ещё группируются по растению. Паспорт пшеничного набора — `docs/DATASET.md`. Поэтапные отчёты — `docs/stages/`.

## Где что лежит

```
src/app/          страница, загрузка, проверка кадра, пороги уверенности
src/model/        сеть, обучение, предсказание, метрики, сравнение моделей
src/data/         скачивание и подготовка выборок
src/control/      контрольные наборы по классам и прогон через приложение
src/paths.py      пути и чтение yaml
configs/          классы, гиперпараметры, контрольные проверки
models/           stage4.pt, stage10.pt, barley.pt, maize.pt
data/processed/   csv-разбиения без самих картинок
reports/          метрики, матрицы ошибок, сводки обучения
```
